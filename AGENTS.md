# Base44 sandbox notes

Non-obvious things about running this repository (the npm CLI monorepo) in the
Base44 preview sandbox. Everything else follows from `package.json`, the docs
workspace READMEs, and `CONTRIBUTING.md`.

## What the preview shows

The npm CLI is a command-line tool: it has **no web server**. The preview on
port 3000 serves the repository's own documentation site, which is the only
browser-facing artifact here:

- Source markdown: `docs/lib/content/<section>/*.md` + `docs/lib/content/nav.yml`
- Build: `npm run build -w docs` (runs `docs/bin/build.js`, writes `docs/output/**/*.html`)
- Server: `.base44/preview-server.js` (static server for `docs/output`; `/` and the
  section URLs come from `nav.yml`, so no page copy is hand-written)

The docs build is **not** a dev server — after editing markdown, rebuild and reload:

```bash
docker compose -f docker-compose.base44.yml exec app npm run build -w docs
```

The docs build also reads the CLI source (`lib/npm.js`, `lib/utils/cmd-list.js`,
`lib/commands/*`, and command definitions), so editing those changes doc pages too.

## Dependencies: `npm install --no-save`, never `npm ci`

- `node_modules/` is **tracked in git** — this repo commits its bundled
  production dependencies, and `.gitignore` only ignores new files inside it.
- Plain `npm install` rewrites the tracked `package-lock.json` with unrelated
  registry metadata churn, so the compose startup uses `npm install --no-save`,
  which installs devDependencies (tap, the docs build toolchain, etc.) into the
  bind-mounted `node_modules` without touching the lockfile.
- Do **not** run `npm ci`: it deletes `node_modules` and would show the tracked
  bundled dependencies as deletions.
- Only one installer may run at a time — the compose stack therefore runs a
  single app service rather than one per workspace.

## Running the CLI and tests

The host has no language runtime; use the container:

```bash
docker compose -f docker-compose.base44.yml exec app node bin/npm-cli.js --version
docker compose -f docker-compose.base44.yml exec app node bin/npm-cli.js help install
# tests (tap), one file or a directory:
docker compose -f docker-compose.base44.yml exec app npx tap test/lib/commands/install.js
```

The full suite (`npm test`) runs tap over the whole repo and takes a long time;
`node . run test` (the self-hosted CLI) also works inside the container.

## Sandbox specifics

- `BASE44_PREVIEW_MODE` is forwarded into the service as-is. No application
  configuration is gated on it: the preview server binds `0.0.0.0`, serves on
  `PORT` (3000), and does no host/origin allowlisting, so nothing needs a
  sandbox-only override. With the variable unset the container behaves the same.
- `docs/output/`, `docs/content/`, and `man/` are build artifacts generated by
  the docs build; regenerate them rather than editing them.

## Verification

`curl -sI http://localhost:3000/` returns 200 with the generated docs index, and
`curl -s http://localhost:3000/commands/npm-install | head` returns the rendered
`npm install` documentation page.
